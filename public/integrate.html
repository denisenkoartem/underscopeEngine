Plugging Underscope into a listing flow

Underscope is a few small APIs and a page that takes a VIN in the URL. Nothing here needs access to ACV's systems today. These are the connection points a partner would use, and they all work now.

Where it sits

ScanVIPER condition report, photos, scan-tool codes
UnderscopeVerified title, repair estimate, fix vs. sell-as-is with two net ranges
Seller decidesFix and relist, or list as-is, with the evidence attached
LaneDealer wholesale for fixed cars, salvage for as-is

In a pilot it would run silently next to today's lane rules (shadow mode), and only change routing on a small randomized slice, so the lift can be measured before anyone relies on it.

1. Link to it from any listing

Any page that knows a VIN can open a prefilled check. Add run=1 to run it straight away.

http://localhost:3000/?vin=1FTEW1EP6JKD12345&title=clean&mileage=84k&clean=24500&comps=9800%2C10400%2C11200&damage=Front%20bumper%20needs%20replacing.%20Everything%20else%20is%20fine.&airbags=no&frame=no&leaks=no&notes=Runs%20and%20drives&run=1

One parameter per required box (title, mileage, clean, comps, damage, airbags, frame, leaks) and notes for anything else, all URL-encoded. A link with only notes still works when the text answers every required box. run=1 starts the check when nothing required is empty.

2. Bookmarklet: one click from a listing page

Drag this button to your bookmarks bar. On any page showing a vehicle (a dealer listing, an auction lot, a condition report), click it. It finds the VIN on the page, confirms it with the VIN check digit, and opens Underscope with that vehicle.

Fix or sell?

  1. Show the bookmarks bar (Ctrl+Shift+B or Cmd+Shift+B).
  2. Drag the orange button onto it.
  3. Open a listing and click it. Selecting the VIN first works too.

3. Call the APIs

    
All of them accept cross-origin requests, so a partner front end can call them directly.

    
    
      
  • GET /api/vehicle?vin=: year, make, model and engine from the free NHTSA decode.
    • 
      
  • POST /api/parse-notes { text } or { fields, text } (the page's boxes plus the general box): the description as JSON (title, mileage, values, 25 part grades, flags), with the words each value came from and what is still missing.
    • 
      
  • POST /api/repair-estimate { grades, flags, labor_rate }: the cost to repair the graded parts, as a range with one line per part.
    • 
      
  • POST /api/route (the JSON from /api/parse-notes plus vin, vehicle and repair): ACV or Copart, the net range of every exit the title allows, and whether repairing first pays.
    • 
    

    
curl -X POST http://localhost:3000/api/repair-estimate \
  -H "content-type: application/json" \
  -d '{"grades":[{"part":"hood","grade":"replace"},{"part":"front_bumper","grade":"replace"}],
       "flags":{"frame_suspected":false},
       "labor_rate":95}'

  


  

    
What a pilot would swap in

    
    
      
  • VIPER payloads in place of the typed description, mapped onto the same 25-part grades.
    • 
      
  • ACV and Copart sold prices in place of hand-entered comps and wholesale values.
    • 
      
  • Shop invoices in place of our rough repair-cost table.

The decision logic and APIs stay the same; only the inputs get better.
